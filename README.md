# سامانه انتخاب واحد تکاملی — بسته انتقال به Codex

تاریخ آماده‌سازی: ۲۰۲۶-۱۱-۰۲. این بسته نقطه شروع ادامه طراحی و توسعه است؛ موتور ژنتیک، رابط کاربری و برنامه قابل اجرا هنوز نوشته نشده‌اند. فایل واقعی اصلاح‌شده در `data/UniversityDataset_Corrected.xlsx` قرار دارد و بدون تغییر محتوایی کپی شده است.

## پیشرفت توسعه پس از انتقال

**فاز 5A:** [Tournament Selection و Course-Based Crossover](docs/GENETIC_OPERATORS.md) آماده‌اند. تمام ۱۶۱ تست و بررسی ساخت/ارزیابی ۱۰۰ فرزند روی جمعیت ثابت موفق بود. Mutation، Repair و حلقه تکامل هنوز ساخته نشده‌اند؛ ساخت PR و merge این فاز دستی است.

**فاز چهارم:** [Population Initialization و نتایج آزمایش](docs/POPULATION_INITIALIZATION.md) آماده است. تولید یک کروموزوم یا جمعیت با Context ثابت و Seed محلی، ارزیابی مستقل و گزارش تنوع پشتیبانی می‌شود. ابزار آزمایش: `python scripts/run_initialization_experiment.py --population-size 100 --seed 2026`. همه ۱۳۴ تست پاس شدند؛ حلقه تکامل و عملگرهای ژنتیک همچنان ساخته نشده‌اند. شرح مراحل قدیمی‌تر در ادامه، وضعیت تاریخی آن مرحله است.

**فاز سوم:** [EvaluationContext، فرمول‌ها و API مطلوبیت نرم](docs/SOFT_FITNESS.md) پیاده شده‌اند. برای یک اجرا، Context را یک‌بار بسازید و در همه ارزیابی‌ها نگه دارید. Hard و Soft مستقل گزارش می‌شوند و مقایسه با `(HardPenalty,-SoftScore)` است. پیش‌فرض Soft طبق آخرین پاسخ کاربر «پوشش × رضایت» است. جمعیت اولیه و عملگرها هنوز ساخته نشده‌اند. این مرحله برای بازبینی معماری در شاخه جدا نگهداری می‌شود؛ توضیح‌های «Soft هنوز وجود ندارد» در بخش‌های پایین، وضعیت تاریخی مراحل قبلی‌اند.

**فاز دوم:** ارزیاب مستقل قیود سخت در `src/scheduler/constraints.py` پیاده شده است. [قرارداد API، شمارش نقض‌ها و نتیجه آزمون](docs/HARD_CONSTRAINTS.md) را ببینید. تابع `evaluate_hard_constraints(chromosome, dataset)` نتیجه مستقل می‌دهد و cache یا ورودی‌ها را تغییر نمی‌دهد. Soft Fitness، جمعیت اولیه و عملگرهای ژنتیک هنوز ساخته نشده‌اند. بخش‌های قدیمی‌تر زیر، پیشرفت مراحل قبل را ثبت کرده‌اند.

مدل کروموزوم و کنترل صحت ساختاری آن نیز ساخته شده است؛ [راهنمای مدل کروموزوم](docs/CHROMOSOME.md) نمونه استفاده، کپی مستقل و مرز صحت ساختار با اعتبار جواب را توضیح می‌دهد. تولید جمعیت و ارزیاب Fitness مرحله بعدند.

محدوده مورد تأکید کاربر: فعلاً توسعه و آزمون برای **یک دانشکده** با دادهٔ ناقص و تصادفی است؛ دانشگاه کامل مرحله بعد است. تعدادها و توزیع تقاضای این فایل مشخصات ثابت موتور نیستند. بررسی تشکیل‌پذیری گروه‌ها اختیاری است و مانع توسعه روی این نمونه نمی‌شود؛ برای مشاهده آن `--diagnostics` را به فرمان اعتبارسنجی اضافه کنید. خطاهای ساختاری مثل شناسه تکراری یا ارجاع شکسته همچنان گزارش می‌شوند.

بخش خواندن و اعتبارسنجی داده و مدل‌های نوع‌دار با Python ساخته شده‌اند؛ موتور ژنتیک و Fitness هنوز ساخته نشده‌اند. گزارش مرحله جاری و تنظیمات پیشنهادی در `docs/IMPLEMENTATION_STATUS.md` و `docs/DESIGN_DECISIONS.md` است. ZIP انتقال و MANIFEST نسخه اولیه ثابت مانده‌اند؛ کد و اسناد جدید در پوشه همین پروژه‌اند و فعلاً در آن ZIP نیستند.

برای اجرای اعتبارسنجی جدید از ریشه پروژه:

```powershell
python scripts/validate_dataset.py --output outputs/INPUT_VALIDATION.json
```

برای اجرای آزمون‌ها:

```powershell
$env:PYTHONPATH = 'src'
python -m unittest discover -s tests -v
```

Python 3.11 یا بالاتر لازم است؛ روی Python 3.13 این سیستم بررسی شده است. نیازی به نصب کتابخانه جدید نیست. خروجی موفق اعتبارسنجی به معنی ساخته‌شدن یا معتبر بودن یک برنامه زمان‌بندی نیست. خطای ورودی با شیت و آدرس سلول و کد خروج ۱ گزارش می‌شود؛ هشدار تقاضای کم مانع خواندن داده نمی‌شود.

## از کجا شروع کنم؟

۱. ZIP را دانلود کن. در File Explorer ویندوز روی آن راست‌کلیک و Extract All را انتخاب کن. برای مسیر ساده از `C:\Projects` استفاده کن تا پوشه نهایی `C:\Projects\UniversityCourseScheduler` باشد. اگر این مسیر مجوز نداشت از پوشه‌ای در حساب خودت استفاده کن. پروژه را مستقیماً داخل ZIP باز نکن.

۲. Codex را باز کن و با حساب خودت وارد شو. از انتخاب پوشه/افزودن پروژه، **پوشه UniversityCourseScheduler دارای همین README و AGENTS.md** را انتخاب کن؛ نام دکمه ممکن است با نسخه برنامه فرق کند. فایل Excel به‌تنهایی پروژه نیست. اگر همین پوشه فعلی را در Codex باز کرده‌ای، نیازی به انتقال دوباره نداری.

۳. در همان پروژه یک گفت‌وگو باز کن و متن `docs/CODEX_START_PROMPT.md` را ارسال کن. از Codex بخواه ابتدا قوانین و اسناد را بخواند و گزارش ممیزی و طرح معماری بدهد. در این مرحله نیازی به نصب بسته‌های موتور، خرید سرویس یا راه‌اندازی وب‌سایت نیست.

۴. داده‌ها و پرسش‌های `docs/DESIGN_DECISIONS.md` را مرور کن. به‌خصوص معنای Target، پیش‌فرض عدم ثبت Availability، سخت یا نرم بودن حداقل بار استاد و نحوه شمارش نقض‌ها باید پیش از پیاده‌سازی Fitness نهایی شوند. جزئیات پیشنهادی با تصمیم تأییدشده یکسان نیستند.

۵. پس از بررسی معماری، کار را مرحله‌ای ادامه بده: ورودی و اعتبارسنجی → مدل دامنه و کروموزوم → محدودیت و Fitness → مقداردهی اولیه → عملگرها و Repair → اجرای آزمایش‌ها → خروجی ساده. برای هر مرحله از معیار پذیرش REQUIREMENTS استفاده کن.

## بررسی اختیاری با PowerShell در Windows

برای خواندن مستندات هیچ ابزار توسعه‌ای لازم نیست. فقط برای تکرار ممیزی، Python 3 لازم است. در صورت نصب بودن، `py --version` باید نسخه را نشان دهد. این ممیزی تنها از کتابخانه استاندارد استفاده می‌کند و نصب وابستگی ندارد.

```powershell
Set-Location -LiteralPath 'C:\Projects\UniversityCourseScheduler'
py -3 scripts/inspect_dataset.py
Get-FileHash -LiteralPath 'data/UniversityDataset_Corrected.xlsx' -Algorithm SHA256
```

اگر فرمان `py` شناخته نشد ولی Python نصب است، `python scripts/inspect_dataset.py` را امتحان کن؛ در غیر این صورت Python 3 را از وب‌سایت رسمی Python نصب کن. این اسکریپت Excel را تغییر نمی‌دهد و گزارش JSON را بازتولید می‌کند. گزارش، اثبات امکان ساخت برنامه معتبر نیست. Excel برای این بررسی لازم نیست. برای توسعه بعدی Python و Git پیشنهادند؛ زبان و وابستگی‌های موتور هنوز تصمیم قطعی پروژه نیستند. اکنون requirements.txt ساختگی یا دستور اجرای موتور وجود ندارد.

اگر نصب یا اجرا نیاز به بررسی داشت، متن خطا را در همین پروژه به Codex بده. تغییر تنظیمات امنیتی PowerShell یا فعال‌کردن دسترسی کامل برای این بسته لازم نیست. هنگام باز بودن فایل در Excel، آن را بی‌دلیل ذخیره مجدد نکن تا نسخه مبنا و هش حفظ شود.

## وضعیت و منابع

۵۷ کنترل ساختاری اجرا شده‌اند و نقضی در آن‌ها ثبت نشده است؛ محدودیت پوشش و هش در DATASET_AUDIT آمده‌اند. ۳۶ درس تقاضای مثبت کمتر از ۸ دارند و ۴ درس تقاضا ندارند. این موارد هشدار مدل‌سازی‌اند و نباید با داده‌سازی برطرف شوند.

تنها پنج نوبت از گفت‌وگوی مبنا بازیابی شد و پیوست‌های آن از ابزار در دسترس نبود؛ فایل Excel از مسیر معرفی‌شده توسط کاربر دریافت شد. آرشیو بازیابی در SOURCE_CONVERSATION حفظ شده است. فرمول کامل Fitness در متن بازیابی‌شده وجود ندارد؛ فرمول اجرایی این بسته **پیشنهاد صریح برای تکمیل طراحی** است. ارجاعات پژوهشی داخلی گفت‌وگوی پیشین تأیید نشده‌اند و به‌عنوان استناد علمی این بسته استفاده نمی‌شوند.

راهنمای محصول بر اساس مستندات رسمی OpenAI در تاریخ بالا نوشته شده است: [Windows](https://learn.chatgpt.com/docs/windows/windows-app)، [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md). راهنمای پروژه در AGENTS.md قرار می‌گیرد؛ مرز دسترسی ابزارها از تنظیمات برنامه می‌آید، نه از این فایل.
