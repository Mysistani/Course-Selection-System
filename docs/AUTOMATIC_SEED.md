# Seed خودکار و بازتولید اجرای وب

پیش‌فرض فرم «آزمایش جدید»، **تولید خودکار Seed** است؛ فیلد دستی غیرفعال و بدون مقدار پیش‌فرض است. با «ورود دستی Seed» می‌توان Seed نمایش‌داده‌شدهٔ اجرای قبلی را وارد کرد. عنوان «Seed استفاده‌شده در این اجرا» در صفحه‌های اجرا، و مقدار `settings.random_seed` در جزئیات، تاریخچه، metadata و گزارش نهایی ذخیره و نمایش داده می‌شود.

## قرارداد API

`POST /api/runs`:

```json
{"dataset_id":"<id>","seed_mode":"auto","settings":{"population_size":100}}
```

در حالت auto، کلید `random_seed` باید حذف شود؛ فرستادن هم‌زمان آن خطای 422 دارد. در حالت manual، مقدار صحیح اجباری است:

```json
{"dataset_id":"<id>","seed_mode":"manual","settings":{"random_seed":1234567}}
```

برای سازگاری قدیمی، اگر `seed_mode` حذف یا null باشد: وجود کلید `settings.random_seed` به معنی manual و نبود آن به معنی auto است. مقدار null، bool، float یا رشته برای Seed دستی رد می‌شود؛ به حالت خودکار تبدیل نمی‌شود. mode ناشناخته نیز رد می‌شود. پاسخ Start شامل `seed_mode` و Seed واقعی در `settings.random_seed` است.

بک‌اند ابتدا تنظیمات را با placeholder صحیح و بدون تصادفی‌سازی اعتبارسنجی می‌کند، سپس Dataset/Context و نبود اجرای فعال را بررسی می‌کند. فقط زیر قفل پذیرش اجرای جدید، یک بار `secrets.randbelow(2**32)` فراخوانی و مقدار با `dataclasses.replace` در EvolutionSettings نهایی قرار می‌گیرد. تنظیمات نامعتبر، Dataset نامعتبر، اجرای هم‌زمان ردشده و حالت دستی هیچ Seed خودکاری مصرف نمی‌کنند. مقدار resolved در سراسر یک اجرا ثابت است؛ در هر نسل تولید مجدد انجام نمی‌شود.

بازهٔ خودکار **۰ تا ۴۲۹۴۹۶۷۲۹۵، شامل دو انتها** است؛ موتور فعلی آن را پشتیبانی می‌کند و در JSON/JavaScript دقیق است. موتور و API دستی همچنان هر `int` معتبر Python، از جمله منفی، را حفظ می‌کنند. فرم مرورگر برای جلوگیری از گردشدن، ورودی دستی را به اعداد صحیح امن JavaScript یعنی `[-9007199254740991, 9007199254740991]` محدود می‌کند. تولیدهای مستقل ممکن است تصادفاً یک مقدار بدهند؛ تضمین یکتایی یا retry برای حذف تکرار اضافه نشده است.

CLI و EvolutionSettings مستقل از این قابلیت‌اند؛ پیش‌فرض و Random محلی موتور تغییر نکرده‌اند. `random.seed()` سراسری استفاده نمی‌شود. با Dataset، نسخهٔ الگوریتم، Policy، تنظیمات و Seed یکسان، ژنوتیپ‌ها و نتایج قطعی بازتولید می‌شوند؛ زمان اجرا لزوماً برابر نیست.

آزمون‌های `tests/test_web_seed.py` با mock کردن `secrets.randbelow`، پیش‌فرض فرم، مرز Seed، فراخوانی مستقل هر اجرای پذیرفته‌شده، عدم retry حتی در تکرار مقدار، حالت دستی/قدیمی، ورودی بد، عدم تولید در درخواست ردشده، persistence، برابری جمعیت auto→manual، توقف و عدم تغییر RNG سراسری را بررسی می‌کنند. هیچ فایل موتور، Fitness، عملگر یا Dataset در این قابلیت تغییر نکرده است.

## نتیجهٔ بررسی — ۲۰۲۶-۱۱-۰۳

۱۰ تست اختصاصی Seed و تمام ۲۸۷ تست پروژه موفق شدند؛ بررسی نحوی JavaScript نیز موفق بود. تست کامل در کپی مستقل با source جدید، Initialization نسخهٔ committed و Datasetهای Git اجرا شد. در پوشهٔ کاری، تغییر قبلی Initialization حفظ شده و فایل B در برنامهٔ دیگری قفل است؛ سه تست دسترسی به B در اجرای اولیه با PermissionError روبه‌رو شدند. کپی Dataset B از Git با هش مرجع `6b90c1c6784cbb81527dfc196e1a5e4347cd56ff988f6ce703a1452093576391` بررسی شد؛ هیچ فایل ورودی مبنا تغییر نکرد.

در مرورگر واقعی روی سرور آزمایشی جدا، فرم به‌صورت پیش‌فرض auto بود و حالت دستی فعال/غیرفعال شد. دو اجرای فقط نسل صفر با جمعیت ۳ روی Dataset A انجام شدند: auto مقدار `1181059628` تولید کرد؛ ورود دستی همین مقدار، تنظیمات و fingerprint یکسان `6eed5fc43979fc3621249f32da67084e20e84cd4c3c65ac9d9f51c8777008875` داد. Seed در پاسخ Start، صفحه، metadata، history و گزارش هر دو اجرا تطبیق داده شد. تست واحد بازتولید علاوه بر این، سه نسل کامل و برابری کل جمعیت نهایی را بررسی می‌کند.

چون روی پورت ۸۰۰۰ یک اجرای کاربر فعال بود، آن سرور restart یا متوقف نشد؛ پیش‌نمایش جدید روی پورت ۸۰۰۱ با storage مستقل اجرا شد. برای استفاده از نسخهٔ جدید روی پورت پیش‌فرض، پس از اتمام اجرای جاری سرور را بسته و `start_ui.bat` را دوباره اجرا کنید؛ refresh مرورگر به‌تنهایی کد Python یک سرور قدیمی را تعویض نمی‌کند.
